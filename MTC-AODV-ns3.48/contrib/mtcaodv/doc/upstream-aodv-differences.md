# Divergence from ns-3.48 `src/aodv`

Generated by un-renaming the fork and diffing against upstream, so the output
shows only behavioural divergence, not the coexistence renames.

```bash
sed 's/BlackholeAodvRoutingProtocol/RoutingProtocol/g; s/mtcaodv/aodv/g' \
    contrib/mtcaodv/model/blackhole-aodv-routing-protocol.cc \
  | diff - <ns3>/src/aodv/model/aodv-routing-protocol.cc
```

The blueprint (§3.2) requires every divergence to be documented. This file is
that record, and it is regenerable, so it cannot silently go stale.

## Summary

| Divergence | Lines | Nature |
|---|---:|---|
| Provenance and divergence notice | ~30 | comment block, no behaviour |
| Trace sources `ForgedReply` and `AttackDrop` | ~12 | observability only |
| `SetAttackBehavior` / `GetAttackBehavior` | ~12 | new public API |
| `SendForgedReply` | ~55 | new method; AODV serialization of policy output |
| Hook 1 in `RecvRequest` | ~22 | inert without a policy |
| Hook 2 in `Forwarding` | ~30 | inert without a policy |
| `DoDispose` releases the policy | 1 | lifetime |

No other upstream statement is altered. Because the AODV support types are
consumed from `src/aodv` rather than forked, a future ns-3 upgrade is handled
by re-forking one file and re-applying this delta.
